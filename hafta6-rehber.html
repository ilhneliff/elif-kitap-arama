Hafta 6 — React Rehberi

Beyinsize anlatir gibi, gunluk dille, bolca benzetmeyle.

Gun 1 — useEffect: Bilesen Yuklenince Veri Cek

useEffect ne is yapar?

React'te bir bilesen (component) ekrana cizildiginde, bazen "ekstra isler" yapman gerekir. Mesela: internetten veri cekmek, bir zamanlayici kurmak, sayfa basligini degistirmek... Bunlara "yan etki" (side effect) deniyor.

useEffect React'e soyle diyor: "Bu bilesen ekrana geldiginde (ya da bir sey degistiginde) su isi de yap."

Benzetme: Restoran garsonunu dusun

Sen bir masaya oturdun (bilesen ekrana geldi). Garson sana menu getiriyor (useEffect calisti). Garson menuleri sadece sen masaya ILCE oturdugun anda getiriyor, her nefes aldiginda degil. Iste useEffect(() => {...}, []) tam olarak bu: "Bilesen ilk kez ekrana geldiginde bir kere calis, sonra rahat birak."

Kod ne yapiyor, satir satir?

import { useEffect, useState } from 'react'

function KitapListesi() {
  // 1. Bos bir liste olustur (baslangicta hic kitap yok)
  const [kitaplar, setKitaplar] = useState([])

  // 2. Bilesen ekrana gelince su isi yap:
  useEffect(() => {

    // 3. Internetten veri ceken bir fonksiyon tanimla
    async function kitaplariGetir() {
      const res = await fetch('https://openlibrary.org/search.json?q=harry+potter&limit=5')
      const veri = await res.json()
      // 4. Gelen veriyi state'e koy (liste artik dolu!)
      setKitaplar(veri.docs)
    }

    // 5. O fonksiyonu hemen cagir
    kitaplariGetir()

  }, [])  // <-- BOS DIZI: "sadece bir kere calis" demek

  // 6. Kitaplari ekranda goster
  return (
    <ul>
      {kitaplar.map((k) => (
        <li key={k.key}>{k.title}</li>
      ))}
    </ul>
  )
}

Peki neden fonksiyonu icinde tanimliyoruz?

React'in bir kurali var: useEffect'e verdigin fonksiyon dogrudan async olamaz. Yani su YANLIS: 

// YANLIS — bunu yapma
useEffect(async () => {
  const res = await fetch(...)
}, [])

Cozum: icerde ayri bir async fonksiyon tanimla, sonra hemen cagir. Dusun ki useEffect sana "is yap" diyor ama "async is" istemiyor. Sen de icerde bir yardimci cagiriyorsun, o yardimci async olabiliyor.

Bagimlilik dizisi (ikinci parametre) ne demek?

useEffect'in ikinci parametresi olan dizi, React'e "bu efekti NE ZAMAN tekrar calistir" sorusunun cevabini verir.

Benzetme: Alarm kurmayi dusun

[] (bos dizi): "Sadece sabah ilk uyandirdiginda cal" — bir kere calar, biter.
[sorgu]: "Sorgu her degistiginde cal" — sorgu degistikce tekrar tekrar calar.
Dizi yok: "HER saniye cal" — surekli calar, deli eder (genelde istemezsin).

Dizi yok — tehlike!
useEffect(() => {
  fetch(...)
})
// HER render'da calisir
// Sonsuz donguye girebilir!
Bos dizi — guvenli
useEffect(() => {
  fetch(...)
}, [])
// Sadece 1 kere calisir
// Tam istedigimiz sey
Gun 1 Ozet

useEffect = "bilesen ekrana gelince su isi yap." Ikinci parametre bos dizi [] verirsen sadece bir kere calisir. Icinde fetch ile internetten veri cekersin, useState ile o veriyi tutarsin.

Gun 2 — Controlled Form: Kullanicidan Girdi Alma

Controlled component ne demek?

Normal HTML'de bir <input> kutusu kendi degerini kendi tutar — tarayici yonetir. Ama React'te biz diyoruz ki: "Hayir, input'un degerini BEN yonetirim, state'imde tutarim." Buna controlled component (kontrollu bilesen) deniyor.

Benzetme: Kukla tiyatrosu

Normal input = kukla kendi basina hareket ediyor, sen sadece seyrediyorsun.
Controlled input = kuklayi SEN oynatiyorsun ipleriyle. Her hareketi sen kontrol ediyorsun.

Ipler ne?
value={sorgu} = "input'un gosterdigi sey benim state'imden gelsin"
onChange = "kullanici bir tus basinca bana haber ver, state'i guncelleyeyim" 

function AramaKutusu() {
  // "sorgu" diye bir state tut, baslangicta bos string
  const [sorgu, setSorgu] = useState('')

  return (
    <input
      value={sorgu}                              // input ne gostersin? state'teki degeri
      onChange={(e) => setSorgu(e.target.value)}  // tus basinca state'i guncelle
      placeholder="Kitap ara..."
    />
  )
}

Bu dongu nasil calisiyor?

  1. Kullanici klavyede "H" tusuna basar
  2. onChange tetiklenir, e.target.value = "H"
  3. setSorgu("H") cagirilir — state artik "H"
  4. React bileseni yeniden cizer, input artik "H" gosteriyor
  5. Kullanici "a" basar, ayni dongu: state "Ha" olur, input "Ha" gosterir...
Peki neden boyle yapiyoruz? Input zaten kendi degerini tutuyor, neden React'e verelim?

Cunku state'te tutunca degeri PROGRAMATIK olarak da degistirebilirsin! Mesela bir "Temizle" butonu eklersin: <button onClick={() => setSorgu('')}>Temizle</button> — butona tikla, input bos olsun. Normal HTML input'ta bunu yapmak cok daha zor.

Form submit ve e.preventDefault()

HTML'de bir form'un icindeki butona basinca ya da input'ta Enter'a basinca tarayicinin VARSAYILAN davranisi sayfayi komple yenilemektir. React'te sayfa yenilenirse tum state kaybolur — felaket!

Benzetme: Kapinin otomatik kapanmasini engellemek

Bir kapidan gecerken kapi otomatik kapaniyor (tarayicinin varsayilan davranisi = sayfayi yenile). Sen kapinin onune ayagini koyuyorsun: "dur, kapanma!" diyorsun. e.preventDefault() = ayagini kapinin onune koymak. "Tarayici, senin varsayilan davranisini (sayfayi yenilemeyi) ENGELLE." 

const gonderildi = (e) => {
  e.preventDefault()  // sayfayi yenileme!
  console.log('Aranan:', sorgu) // artik state kaybolmadan isini yapabilirsin
}

return (
  <form onSubmit={gonderildi}>
    <input value={sorgu} onChange={(e) => setSorgu(e.target.value)} />
    <button type="submit">Ara</button>
  </form>
)
Gun 2 Ozet

Controlled input = input'un degerini state'te tutmak. value={state} + onChange={guncelle} ikilisi. Form submit'te e.preventDefault() ile sayfanin yenilenmesini engelle.

Gun 3 — Durum Render: Loading / Bos / Hata

Neden 3 ayri durum var?

Internetten veri cektigin zaman her sey hep guzel gitmez. Uc sey olabilir:

  1. Veri henuz gelmedi — internet yavas, sunucu dusunuyor. Kullaniciya "yukleniyor" de.
  2. Bir hata oldu — internet koptu, sunucu coktu. Kullaniciya "hata oldu" de.
  3. Veri geldi ama bos — arama sonucu yok. Kullaniciya "sonuc bulunamadi" de.
Benzetme: Kargo takibi

Internetten bir sey siparis ettin. Kargo takip sayfasi sana 3 farkli mesaj gosterebilir:
"Kargonuz yolda" = yukleniyor (loading)
"Kargo kayboldu" = hata (error)
"Bu siparis numarasina ait kargo bulunamadi" = bos (empty)

Eger kargo takip sayfasi bu 3 durumu GOSTERMESEYDI, sen sadece bos beyaz ekrana bakip "site bozuk mu, kargom kayip mi, ne oluyor?" diye dusunurdun. KOTU deneyim.

3 state ile 3 durumu yonetmek

const [sonuclar, setSonuclar] = useState([])       // sonuclar listesi
const [yukleniyor, setYukleniyor] = useState(false) // yukleniyor mu?
const [hata, setHata] = useState(null)              // hata var mi?

try / catch / finally ne demek?

Benzetme: Yumurta kirmak

try = "yumurtayi kirmayi DENE" — her sey yolunda gidebilir
catch = "eger yumurta yere duserse, YAKALA ve temizle" — hata olursa ne yapacagini soyle
finally = "yumurta kirilsa da kirilmasa da, sonunda ellerini YIKA" — ne olursa olsun calisir 

const ara = async (sorgu) => {
  setYukleniyor(true)   // "yukleniyor" moduna gec
  setHata(null)          // onceki hatayi temizle

  try {
    // internetten veri cekmeyi DENE
    const res = await fetch(`https://openlibrary.org/search.json?q=${sorgu}&limit=10`)
    if (!res.ok) throw new Error('Sunucu hatasi')
    const veri = await res.json()
    setSonuclar(veri.docs) // basarili! sonuclari kaydet

  } catch (err) {
    // bir sey ters giderse hatayi YAKALA
    setHata(err.message)

  } finally {
    // basarili da olsa, hata da olsa: yukleme BITTI
    setYukleniyor(false)
  }
}

Ekranda hangi durumu gosterecegiz?

Sirayla kontrol et: ilk eslesen durumu goster, gerisini gosterme. 

// Her kontrolde: eger bu durum gecerliyse, sadece BUNU goster ve dur

{yukleniyor && <p>Yukleniyor...</p>}
{hata && <p>Hata: {hata}</p>}
{!yukleniyor && !hata && sonuclar.length === 0 && <p>Henuz sonuc yok.</p>}

// Hicbiri degilse: sonuclari listele
<ul>
  {sonuclar.map((k) => <li key={k.key}>{k.title}</li>)}
</ul>
Sira neden onemli?

Yukleniyor'u en basta kontrol etmezsen, yukleme sirasinda hem "yukleniyor" hem "henuz sonuc yok" mesajlari ayni anda gorulur — cunku yukleme sirasinda sonuclar dizisi hala bos! Once yukleniyor'u kontrol edersen, diger kontrollere hic girmez.

Gun 3 Ozet

Internetten veri cekerken 3 durum olabilir: yukleniyor, hata, bos. Her biri icin ayri state tut, ekranda sirayla kontrol edip dogru mesaji goster. try/catch/finally ile hem basarili hem basarisiz senaryolari yonet.

Gun 4 — Lifting State Up: State Nerede Yasamali?

Sorun ne?

Diyelim iki bilesen var: AramaKutusu (kullanicinin yazdigi yer) ve SonucListesi (sonuclari gosteren yer). Ikisi de ayni veriye ihtiyac duyuyor — mesela arama sorgusu.

Ama React'te kardes bilesenler birbirinin state'ine ERISEMEZ. AramaKutusu'nun icindeki sorgu'yu SonucListesi goremez.

Benzetme: Iki oda arasinda mesaj gondermek

Iki kardes oda dusun, arada duvar var. Sol odadaki kisi (AramaKutusu) bir sey yaziyor, sag odadaki kisi (SonucListesi) o yaziyi gormek istiyor. Ama duvar var, goremez!

Cozum: Yaziyi odalardan birine degil, koridora (ortak alan = App) koy. Iki oda da koridora bakabilir. Koridordaki yazi degisince iki oda da gorur.

Iste bu "yaziyi koridora tasima" islemine lifting state up deniyor.

Yanlis yaklasim

// YANLIS: sorgu AramaKutusu'nun ICINDE hapsolmus
// SonucListesi bu veriye ERISEMEZ

function AramaKutusu() {
  const [sorgu, setSorgu] = useState('')  // state BURADA
  return <input value={sorgu} ... />
}

function SonucListesi() {
  // sorgu'ya nasil ulasacagim?? YOLU YOK!
  return <p>???</p>
}

Dogru yaklasim: State'i yukari tasi

// DOGRU: state en yakin ortak atada (App)
// Cocuklara props ile gecir

function App() {
  const [sorgu, setSorgu] = useState('')  // state BURADA, yukaridsa

  return (
    <div>
      {/* AramaKutusu'na state'i degistirme gucu ver */}
      <AramaKutusu sorgu={sorgu} setSorgu={setSorgu} />

      {/* SonucListesi'ne state'i okuma gucu ver */}
      <SonucListesi sorgu={sorgu} />
    </div>
  )
}

// AramaKutusu artik KENDI state'i yok, props ile aliyor
function AramaKutusu({ sorgu, setSorgu }) {
  return <input value={sorgu} onChange={(e) => setSorgu(e.target.value)} />
}

// SonucListesi de props ile aliyor
function SonucListesi({ sorgu }) {
  return <p>Aranan: {sorgu}</p>
}
Benzetme: Aile borcesi

Dusun ki aile toplantisinda yemek kim siparis edecek?

Yanlis: Her cocuk kendi basina farkli restoran ariyor. Biri pizza, biri sushi siparis ediyor. Kaos!

Dogru: Anne/baba (App) karar veriyor: "Pizza yiyecegiz." Bir cocuga (AramaKutusu) siparis verme gorevi verir, diger cocuga (SonucListesi) "pizza geldi, masayi kur" der. Karar TEK bir yerde, herkes oradan ogreniyor.

Senin projen nasil olmali?

Tam olarak bu yapi:

function App() {
  // TUM state'ler burada
  const [sorgu, setSorgu] = useState('')
  const [sonuclar, setSonuclar] = useState([])
  const [yukleniyor, setYukleniyor] = useState(false)
  const [hata, setHata] = useState(null)

  // Arama fonksiyonu da burada
  const ara = async (sorgu) => { ... }

  return (
    <div>
      {/* AramaKutusu: sorgu'yu DEGISTIRME gucu + arama tetikleme */}
      <AramaKutusu sorgu={sorgu} setSorgu={setSorgu} aramaYap={ara} />

      {/* SonucListesi: sonuclari GOSTERME gorevi */}
      <SonucListesi sonuclar={sonuclar} yukleniyor={yukleniyor} hata={hata} />
    </div>
  )
}

Props drilling ne?

State'i yukari tasiyinca veriyi cocuklara props ile gecirmek zorundasin. Eger bilesenler cok ic ice gecmisse (buyuk buyuk ata → ata → ebeveyn → cocuk), veri her seviyeden geciyor — buna props drilling deniyor.

Benzetme: Fisildama oyunu

Siraya dizilmis 5 kisi var. Ilk kisi bir mesaj soyluyor, ikinci kisiye fisildatiyor, o ucuncuye, o dorduncuye... ta ki mesaj son kisiye ulasana kadar. Aradaki kisiler mesaji KULLANMIYOR, sadece aktariyor. Bu biraz zahmetli ama 2-3 kisi icin sorun degil. 5-6 kisiyi gecerse daha iyi yontemler var (useContext gibi — ileride ogreneceksin).

Altin kural

"Iki bilesen ayni veriye ihtiyac duyuyorsa, o veriyi ikisinin de ortak atasinda tut."

State yukari cikar, props asagi iner. Her zaman. Bu kadar.

Gun 4 Ozet

Kardes bilesenler birbirinin state'ine erisemez. Cozum: state'i en yakin ortak ataya tasi (lifting state up), cocuklara props ile gec. AramaKutusu state'i degistirir, SonucListesi okur — ikisi de App'teki tek dogruluk kaynagina bagli.
